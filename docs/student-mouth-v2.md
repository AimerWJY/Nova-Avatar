# 修复v1闭嘴不动：局部嘴部解码器

本次使用同一已审核素材和v1 checkpoint，针对“嘴没有张开”做局部修复。
实现为mouth_refinement_v2，共864376参数，其中350707参数参与本轮训练。
这是同一训练片段上的拟合验证，不是通用口型或手机部署已经完成。

## 诊断与改动

已逐帧查看教师嘴部：第12、24、68帧明显张口，第20、72、76帧闭口。
v1在这些张口帧仍接近原图的闭嘴状态。原有较宽ROI包含鼻下和脸颊，
整脸的原图保留通路又容易得到较低像素误差，宽ROI误差下降不能证明学会张嘴。

新结构冻结v1全部权重，保留其已有脸部、头肩及背景输出，
仅学习固定嘴部区域[103,101,153,133]的补充像素。
局部解码器接收原图/原模型嘴部图像、8帧音频特征及当前时序状态，
在64×64局部特征上解码，缩回原区域并在边界渐变融合。
初始化时修正量为零，不改变原模型结果。

监督聚焦到[110,108,148,128]的嘴唇/嘴腔核心，使用：

| 损失 | 权重 |
| --- | --- |
| 核心RGB L1 | 1 |
| 核心边缘差分L1 | 0.5 |
| 教师软暗区BCE | 0.1 |
| 暗区面积代理L1 | 1 |
| 与前一帧的核心差分L1 | 0.5 |

软暗区为sigmoid((0.22-luma)/0.04)，亮度系数[0.299,0.587,0.114]。
每批从教师暗区面积最高/最低四分位各取一半样本，并同时训练其前一帧。
这是按暗区代理均衡采样，不是声学或关键点检测得到的真实张口标签。
训练目标直接来自对应教师帧，不在推理时读取教师图像、帧编号或人为指定张嘴时间。

## 复现

```bash
cache/student-venv/bin/python scripts/student_mouth_train.py \
  --dataset data/emotion-overfit-001/manifest.json \
  --base-checkpoint outputs/emotion-reference-v1-001/checkpoint.pt \
  --output outputs/emotion-mouth-v2-001 --steps 1200 --device cpu
```

云端使用`bash scripts/cloud.sh student-mouth-train`，其余参数相同，并改为数据盘绝对路径。
源数据、v1权重保持原样；输出目录必须不存在。
训练启动时校验来源清单与v1对应，结束时逐参数验证冻结权重没变化。
完整序列再逐像素验证嘴部补丁之外与v1完全一致。

## 2026-11-05实际结果

CPU执行1200步、batch size 8、Adam lr=0.001，约68秒。
所有指标在完整78帧、4.875秒训练片段上计算，不能外推新人物或新语音。

| 同一嘴部核心区域指标 | v1修复前 | v2修复后 |
| --- | --- | --- |
| RGB MAE | 0.06973 | 0.03741 |
| 边缘差分MAE | 0.03932 | 0.02873 |
| 帧间差分MAE | 0.05454 | 0.03921 |
| 暗区面积代理MAE | 0.03026 | 0.00759 |
| 暗区代理的序列标准差 | 0.00522 | 0.03099 |

教师暗区代理序列标准差0.03048；修复后暗区代理与教师的相关系数约0.915。
该代理受阴影、唇色和牙齿影响，**不是嘴唇开合比、SyncNet分数或口型同步验收结果**。
修复后正确音频的核心RGB误差0.03741，错位半段音频后0.12723；
这只支持当前训练片段上的条件拟合，不证明独立音频泛化。
本页核心区域与v1报告的宽ROI不同，不应跨区域混比误差。

已查看包含张口与闭口的8个时刻（0、12、20、24、39、68、72、76帧）：
第12、24、68帧修复后可见张口，闭口帧没有被一律强行撑开。
牙齿仍有模糊、局部边缘/颜色仍有瑕疵，手势没有通过这次嘴部修复改善。
补丁外最大像素差为0，冻结v1参数逐项未改变。

产物位于outputs/emotion-mouth-v2-001：

```text
teacher_v1_v2.mp4    # 同样顺序的整帧对比
student.mp4         # 修复后的整段输出

```

局部放大图只是把256图中的原像素放大展示，不代表更高生成分辨率。
v2仍采用固定区域，仅适用于本次构图；换人物、明显转头或位置移动时需要重新定位/追踪。
没有新增独立验证集、ASR或专用唇音同步评估。手机导出与新结构性能尚未接入，
lip_sync_verified、generalization_verified及phone_validated均为false。
v0的ncnn导出器会拒绝v2，不能将其当成已经可运行的手机模型。
